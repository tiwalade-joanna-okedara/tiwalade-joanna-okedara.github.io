Prompt engineering

Real prompts from my projects, and why each one is written the way it is.

An assistant system prompt

Structure I use for in-product assistants.

# Role, scoped to one business
You are the assistant helping {business} run their business.

# Context, injected fresh on every call
Recent contacts, open tasks, money this month,
active forms, connected channels.

# Rules
Keep replies short. End with one action or one question.
Before creating or changing anything, show a preview
and ask for confirmation.
Use the user's real data. Never make up names or numbers.
Plain language. No jargon.

Context goes in on every call so answers use real numbers. The confirm rule is the guardrail that makes it safe to let AI act.

A writing style guide as a prompt

From my LinkedIn reply helper.

Sound like a person, not a brand. Short sentences.
Respond to the specific thing they said.
If they asked a question, answer it.
One idea per reply. Two or three sentences at most.
British spelling. No em dashes. No hashtags.
Never invent numbers, results or promises.
If someone disagrees, agree with what's fair
and add something useful.
If a comment is spam or rude, output SKIP.

Rules are concrete enough to check. SKIP gives the model a safe way out, so it doesn’t force a reply to spam. The author still approves every draft.

A drafting prompt with an honesty check

From my brief builder.

Write a first draft from this brief.
Plain British English, no em dashes,
no filler intro, no invented statistics.
Mark anything that needs a real source
as [SOURCE NEEDED].

{brief}

The model can’t verify facts, so the prompt makes gaps visible instead of hidden. The editor fills them.

What I test before a prompt ships

  • Ten real inputs, including messy and rude ones
  • Does it refuse or stop when it should?
  • Does it ever invent a number or a name?
  • Is the output short enough to read on a phone?
  • For voice: real accents, Pidgin and noisy audio
